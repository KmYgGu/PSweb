# 픽셀 오토 배틀 (프로토타입)

HTML/CSS/바닐라 JS + Canvas. 빌드 과정 없음. `python3 -m http.server 8080` 실행 후 http://localhost:8080 접속 (index.html 파일을 바로 열어도 동작함).

## 버전 · 캐시 무효화 (커밋할 때마다)
푸시 전에 **`node tools/bump_version.cjs`** 를 실행하고 바뀐 파일(`js/version.js`, `version.json`, `index.html`)을 같이 커밋합니다.
- 버전 형식: 한국 날짜 + 그날 몇 번째 = `2026.11.10-1` (같은 날 다시 실행하면 `-2`, `-3` …). 직접 지정: `node tools/bump_version.cjs --set 2026.11.10-5`. 검사만: `node tools/bump_version.cjs --check` (세 파일 버전이 다르면 종료 코드 1).
- 기준은 `js/version.js` 의 `APP_VERSION` 하나. 메인 화면 제목 옆에 `v버전` 으로 작게 표시(전투 화면에는 없음).
- `index.html` 의 모든 로컬 js/css 주소 뒤에 `?v=버전` 이 붙어서, 새 버전 index.html 을 받으면 스크립트도 전부 새로 받습니다. 캐릭터 그림·초상화(`Sprites`, 듀얼 몬스터)와 효과음(`assets/sfx`)도 `assetV()` 로 같은 `?v=버전` 이 붙습니다 (file:// 에서도 그대로 동작, Node `tools/headless.js` 는 `?v=` 를 떼고 파일을 읽음).
- index.html 자체는 GitHub Pages 가 최대 10분 캐시하고 헤더는 바꿀 수 없습니다. 그래서 웹에서는 시작할 때 `version.json` 을 캐시 없이 한 번 읽어, 실행 중인 버전보다 새 버전이면 주소에 `?_v=새버전` 을 붙여 **한 번만** 새로고침합니다 (주소의 `?_v=` 는 바로 지워짐). 같은 버전으로는 탭마다 한 번만 시도(sessionStorage), 화면을 이미 눌렀거나 메인 화면이 아니면 하지 않음, file:// · 오프라인 · version.json 오류면 아무것도 안 함.
- 리플레이의 "다른 버전에서 저장됨" 판정(`main.js` 의 `BUILD` = 캐릭터·스테이지 목록 해시)과 탈출맵 서버 버전(`server/index.js`, `package.json` 2.0.0)은 이 버전과 별개입니다.

## 스킬 아이콘 줄 (HP 바 아래)
- 폰: 상단 프레임(초상화·이름·HP) 바로 아래 한 줄 (18px, 8개 이상이면 16px). PC 넓은 화면: 오른쪽 패널 HP 바 아래 (22px). 2인 팀은 멤버마다 작은 HP 바 아래에 작은 줄.
- 아이콘은 유닛의 실제 스킬 슬롯(`u.skills`, `hidden` 제외)을 그대로 따라감 → 슈르프가 흡수한 스킬(빼앗긴 캐릭터 색 테두리 + 오른쪽 위 작은 표시), 브로리 LSS 변신 후 스킬로 자동 교체.
- 듀얼리스트(유희·카이바·구울즈)는 카드마다 아이콘을 두지 않고 턴 행동 4칸: 드로우(다음 드로우까지 덮개, 숫자 = 덱 장수) / 몬스터·마법·함정(숫자 = 패의 해당 카드 수).
- 쿨타임: 위에서부터 어두운 덮개(남은 비율) + 오른쪽 아래 남은 초. 준비되면 잠깐 밝아지고, 쓰면(전투 훅 `onSkill`) 커지며 번쩍. 자원 부족(이블린 매듭·베르제브트 마력 등)은 붉은 덮개, 쓸 수 없는 상태(슈르프 드래곤 등)는 어둡게.
- 아이콘을 누르면(마우스는 올리면) 스킬 이름. 그림은 `js/skillicons.js` 의 `ART` (12×12 글자 그림, 팔레트 문자 + `x`=캐릭터 색) → 16×16 PNG 를 캔버스로 생성 (file:// 가능). 새 스킬은 `ART` 에 한 줄 추가 (없으면 기본 별 아이콘).
- 전투 값은 읽기만 함 (난수·리플레이 영향 없음). 동영상 녹화 화면에도 그대로 들어감.

## 스탯 구조
- `STAT_DEFS`: 선택 화면에 보여줄 스탯 `{ key, label, max, fmt? }`
- `STAT_DEFAULTS`: 모든 스탯의 기본값. 캐릭터는 바꾸고 싶은 값만 `stats`에 적으면 됨.
- 유닛 생성 시 `unit.st = { ...STAT_DEFAULTS, ...def.stats }` 로 합쳐짐.
- 현재 엔진이 사용하는 스탯: `hp, atk, spd(px/초), range(px, 80 이상은 원거리), atkRate(초당 공격), def, crit`.
- 버프는 `unit.buffs`에 `{ type, t, 배율키... }`로 넣으며 `unit.mult('키')`로 곱연산 됨 (`spdMul`, `atkRateMul`, `dmgTaken`, `lifesteal`, `reflect`).

### 새 스탯 추가 방법 (예: 방어력/치명타)
`def`, `crit`는 이미 엔진(`Battle.damage`)에 연결되어 있음:
1. `STAT_DEFS`에 `{ key: 'def', label: '방어력', max: 50 }` 추가 → 선택 화면에 막대로 표시됨.
2. 캐릭터 `stats`에 `def: 20` 지정 (없으면 기본값 0).

완전히 새로운 스탯(예: `evasion` 회피):
1. `STAT_DEFAULTS`에 `evasion: 0` 추가.
2. (표시하려면) `STAT_DEFS`에 한 줄 추가.
3. `js/game.js`의 `Battle.damage()` 계산 파이프라인에 한 줄 추가: `if (Math.random() < tgt.st.evasion) return 0;`

## 이동 방식 (핀볼/팽이 스타일)
캐릭터는 서로를 향해 걷지 않습니다. 마찰 없이 `spd`(px/초) 일정 속도로 직진하고, 벽에 닿으면 순수 반사(법선 기준 반사각 ±0.25rad 무작위, 상대 방향 보정 없음 — 전투·탈출맵 공통), 서로 부딪히면 동일 질량 탄성 충돌로 튕겨나가며 잠시 +45% 가속(약 0.6초에 걸쳐 감쇠). 충돌 시 작은 링/스파크, 강한 충돌에만 미세한 화면 흔들림. 이동 중 옅은 잔상. 물리는 1/120초 서브스텝으로 진행해 4배속에서도 터널링 없음. 상대가 사거리 안이면 이동 중 자동 공격/스킬. 근접 캐릭터는 충돌 순간 공격 쿨이 절반 이상 찼으면 즉시 '충돌 타격'. 돌진 스킬은 상대 이동을 예측/추적.

## 전투 규칙: 기본 공격(충돌) · 근접 공격(무기)
- **기본 공격 = 충돌 피해**: 모든 캐릭터(원거리·블레이드·갈포드·2인 팀 유닛·유희 포함)는 상대와 몸이 부딪히면 `ATK × 0.85`(`BUMP_K`, game.js) 피해를 줍니다. 쿨타임은 각자 `1 / atkRate`(`u.bumpT`). 아군끼리는 튕기기만 합니다.
  - 속성은 캐릭터 `attack.element`, 상태이상은 `attackApplies` 를 그대로 사용(전달 방식은 근접). 공중 상태(트램펄린·블레이드 탑승 등)는 충돌하지 않으므로 맞지 않고, 기절/행동 불가 중엔 충돌 피해를 주지 않습니다. 엑조디아 정지 중에는 발생하지 않습니다.
  - 회피·방벽·함정(미러 포스 등 `attack` 이벤트) 규칙은 기존과 같습니다. 축구장 공 차기·건물 규칙은 변경 없음.
- **근접 공격 = 무기 공격**: 사거리 < 80(`MELEE_RANGE`) 캐릭터만, 상대가 무기 사거리 안에 들어오면 자동 공격(`basicAttack`, 기존 동작 · `atkT` 쿨타임). 몸이 닿기 전에도 휘두를 수 있습니다.
  - 충돌 피해와 무기 공격은 **완전히 독립**(쿨타임 별도, 동시 발생 가능).
  - 야구장 타석(스윙은 왼쪽·오른쪽 타석 모두 아래 → 위 올려치기): 근접 무기 스프라이트(`WEAPONS`)나 로켓 해머가 있는 캐릭터는 방망이 대신 그 무기를 같은 자세·스윙으로 휘두릅니다(`Render.heldWeapon`/`drawHeldWeapon`, 그리기 전용). 이블린은 하이힐 다리, 브로리/파라가스는 기 주먹으로 휘두르고(이 둘은 휘두를 때만 보임), 오리(머리 박치기)·무기 없는 캐릭터, 도끼를 던져 손에 없는 미츄헨은 야구 방망이.
  - 야구장 세이프 후 플레이 계속 (v2026.11.10-20, js/baseball.js): 타자가 빈 베이스를 밟으면 그 자리에 멈춰 서고(태그 대상 아님) 주자·수비는 계속 플레이. 주자가 되돌아갈 베이스가 차 있으면 귀루 요청 — 주자는 그 이전 베이스로(연쇄), 세이프된 타자는 풀려나 다시 자유 이동(비켜 준 베이스는 한 번 벗어나야 다시 세이프). 모든 주자가 베이스에 있고 수비가 공을 쥔 채 0.7초면 안타로 플레이 종료(안전장치 10초). 풀려난 타자는 다시 빈 베이스를 밟아야 안타, 태그되면 아웃.
  - 야구장 타격 전 공격 금지 (v2026.11.11, js/baseball.js `BSB_HELD`): 준비·투구·볼 판정·홈런 정지·플레이 종료 연출 중에는 모든 피해(자기·아군 포함)·고정 피해, 상대가 거는 해로운 상태이상, 넉백·끌어오기가 무효. 듀얼리스트(유희·카이바·구울즈)는 턴 진행·카드 사용·몬스터 공격이 멈추고, 라미아 개전 산개·쿨타임 가속도 공을 친 뒤부터.
  - 야구장 AI (v2026.11.11): ① 볼카운트 — 3볼이면 투수는 존에, 타자는 3-0에서 기다림 / 2스트라이크면 투수는 변화구·유인구, 타자는 존 밖도 커트(파울↑, 타구 약간 약함) / 타자 유리 카운트에서 존 공은 타구 +8% ② 수비 위치 — 타자 공격력에 따라 내야 ±20·외야 ±46px 앞뒤로(포수 제외) ③ 포구 — 타격 순간 위치에서 멀리 뛰어가 잡을수록(200px에서 −42%), 빠른 타구(380px/s 초과)일수록 어려움 ④ 송구 — 수비수 송구 기준 완화(들고 쫓을 때보다 22 이상 가까우면, 잡을 만한 주자면 37), 투수 30. 주자 과감도 0.9~1.5

## 벽 충돌 규칙 (장애물 포함)
- `blockAt(x, y, pad)` 은 건물뿐 아니라 스테이지 고체 장애물도 반환합니다: 스트리트 파이트 철망 칸, 열린 공사 타워 해치, 레이싱 중앙 전광판, 정차한 지하철 열차 벽 (스테이지 훅 `solidAt(b, x, y, pad)` → `{ stageSolid, hit(dmg, strong, x, y) }`).
- 그래서 라인하르트 돌진 제압(벽 박기), 신비술사 조종 벽 충돌, 넉백 벽 충돌(데드☆퍼니셔 등 `knockback onWall`), 스플릿블레이드 튕김이 바깥 벽과 똑같이 장애물에서도 발동합니다. `hitBuilding` 이 장애물의 `hit` 을 호출 → 철망 칸/열차 창문 손상 (제압 박기 = 강타, 철망 칸 파괴).
- 블레이드 탑승: 탑승 칼날이 회전하며 닿은 지상 적에게 ATK x0.7 (대상별 0.4초) — 주는 피해로는 하차하지 않음.

## 캐릭터 추가 방법
`CHARACTERS`에 객체 추가: `id, name, color, stats, skills: [...], projectile?('arrow'|'magic'|'holy'), sprite, portrait?`.
스프라이트는 기본 16x16 인체 템플릿 위에 `rows`(행 교체), `rects`, `px`(`pxLine` 헬퍼)로 무기/모자를 덧그림. 팔레트 키: H 머리, S 피부, E 눈, B 몸, A 장식, L 다리, D 신발, W 금속, w 나무, M 마법.

### 스킬 여러 개 (skills 배열)
```js
skills: [
  { id: 'dashSlash', name: '질풍참', cd: 6 },
  { id: 'ironWall',  name: '철벽 방패', cd: 12, canUse: (u, e, d) => u.hp < u.maxHp * 0.5 }, // 슬롯별 사용 조건 재정의(선택)
],
```
- 슬롯마다 독립 쿨타임(`unit.skillT[i]`), 시작 시 쿨의 35~50%가 남은 상태.
- 사용 조건: 슬롯의 `canUse`가 있으면 그것, 없으면 `SKILLS[id].canUse`.
- 같은 프레임에 여러 슬롯이 준비되면 배열 앞쪽이 우선(프레임당 1개 사용).
- 사용 시 하단 로그에 '캐릭터명: 스킬명' 표시, 선택 화면에 스킬 목록 표시. (캐릭터 위에 쿨타임/준비 표시는 없음)
- `use(u, e, b, slot)`의 4번째 인자로 슬롯 객체가 전달되므로 슬롯에 커스텀 값(예: `power: 2`)을 넣어 같은 스킬을 다른 수치로 재사용 가능.

새 스킬은 `js/skills.js`의 `SKILLS`에 `{ desc, canUse(u,e,d,b), use(u,e,b) }` 추가. 사용 가능한 API: `b.damage, b.heal, b.stun, b.windup, b.dash, b.shoot, b.later, b.telegraphLine/Circle/Fan, b.ring, b.puff, b.explosion, b.text, b.clampPos`.

## 스테이지 (`js/stages.js`)
흐름: 캐릭터 2명 선택 → 스테이지 선택(기본 아레나 / 무인도 / 시가지 / 무작위, 그 위에 **경기 집중 모드** 토글 스위치) → 전투. '다시 싸우기'는 같은 스테이지(무작위였다면 뽑힌 스테이지)와 현재 UI 플래그(전투 타입·경기 집중 모드)를 유지. 하단 바와 결과 창에 스테이지 이름 표시(경기 집중이 켜져 있으면 하단 바에 ` · 경기 집중`).

- **몬스터볼 내부**: 원형 경기장(`circle`). 12초부터 32초에 걸쳐 반지름이 150→75로 부드럽게 축소, 3초 뒤 위치를 점선 예고 링으로 표시. 원형 벽은 법선 기준 반사, 축소 시 바깥 캐릭터는 안쪽으로 밀림, 투사체는 벽에서 소멸.
- **풀장**: 공 36개(`balls`, 반지름 7). 캐릭터가 공에 부딪히면 캐릭터끼리 충돌처럼 반사·충격 링·짧은 가속(`boost`), 공은 날아감(돌진 중엔 관통). 정지 상태로 시작, 캐릭터/투사체/충격파(스킬 AoE)에 밀려 공-공·공-벽·공-캐릭터 충돌(공간 격자, 마찰로 서서히 정지, 정지 공은 계산 생략). 공은 피해 없음·사라지지 않음. 캐릭터도 살짝 튕김.
- **무인도**: 섬 바깥(`outsideEllipse`)이 물 구역. 물속 이동속도 x0.6, 받는 속성 피해 전기 x1.4 / 화염 x0.8 / 빙결 x1.05 (`terrain[].resist`). 입수/출수 물보라, 이동 중 물결 파문. 물속에서 머리 위 산소 게이지가 줄고(3초), 0이면 0.5초마다 8 피해, 육지에서 회복(초당 1.5). 경기장 가장자리 반사는 동일.
- **시가지**: 건물 6채(`buildings`). 캐릭터는 건물에 반사되며 충돌마다 건물 피해(`bumpDmg + 속도×bumpSpeedK`). 투사체는 건물에 막히고 피해(`projK`), 근접 공격도 근처 건물 타격(`meleeK`), 폭발/대지 강타/돌진은 강한 타격(`strongMin` 이상이면 즉시 붕괴). 체력에 따라 균열 3단계 → 붕괴 시 잔해·먼지 이펙트 후 통과 가능한 잔해 바닥. 시작 위치는 건물 밖으로 보정, 매 스텝 건물 밖으로 밀어내 끼임 방지.

- **바베큐 불판** (`js/stages8.js`): 숯불 석쇠 위 고기 5개. 고기 위에 선 캐릭터가 많을수록 빨리 익고, 아랫면이 익으면 거대한 손이 뒤집어(0.6초 그림자 예고) 위의 캐릭터를 띄워 기절시키며, 양면이 익으면 집어 가(0.8초 경고) 위의 캐릭터는 먹힘(즉시 패배); 고기 밖에선 머리 위 열기 게이지가 차서 가득 차면 화상·혼란·깡충.
- **수업 중의 교실** (`js/stages8.js`): 선생님(무작위 비참가 캐릭터)이 칠판을 보다 돌아보면 싸우던 캐릭터는 멈춰야 하고, 공중·해로운 상태이상·동작 중이라 못 멈추면 들켜서 교탁 옆으로 끌려가 선생님이 다시 칠판을 볼 때까지 행동 불가; 학생 3~6명(무적·충돌 없음)은 싸움을 구경.

새 스테이지 추가:
```js
swamp: { name: '늪지', desc: '...', theme: 'arena',          // theme: 바닥 그리기 방식 (arena/island/city, game.js의 paint*에 추가 가능)
  spawns: [{ x: 100, y: 330 }, { x: 260, y: 330 }],
  terrain: [{ id: 'mud', shape: { type: 'rect', x: 12, y: 300, w: 336, h: 80 }, spdMul: 0.7, resist: { fire: 0.8 } }],
  buildings: [{ x: 160, y: 200, w: 40, h: 40, hp: 100, style: 1 }] },
```
원형 경기장 키: `circle: { cx, cy, r0, rMin, start, dur }`. 볼풀 키: `balls: { count, r, area, friction, restitution, push, kick, colors }`.
구역 키: `shape(rect|ellipse|outsideEllipse), spdMul, resist, oxygen{max,drain,regen,dmg,tick}, splash(물보라 색)`. 테스트: `BattleSim.simulate(a, b, 300, 'city')`.

## 속성 · 전달 방식 · 관통 (`js/elements.js`)
- **속성(element)**: 베기 slash, 타격 blunt, 화염 fire, 빙결 ice, 전기 elec, 빛 light, 어둠 dark. 모든 피해에 지정 (기본 공격 `attack`, 스킬 슬롯).
- **전달 방식(delivery)**: `melee`(근접) / `ranged`(원거리). 속성과 별개 (활 = 베기+원거리, 창 = 베기+근접).
- **관통(pierce)**: 속성이 아닌 공격 속성값. 대상 방어력의 해당 비율 무시 (`pierce: 0.3` = 방어 30% 무시).
- 캐릭터 `resist: { fire: 0.5, dark: 1.5, ranged: 0.85 }` (속성 또는 전달 방식 키, 없으면 1). 버프에 `resist: {...}` 를 넣어 일시적 저항도 가능.
- 배율 ≥1.05 → 주황 숫자 + '약점!', ≤0.95 → 회색 숫자 + '저항' (`ELEMENT_FX`에서 조정).
- 피해 계산 순서: 공격력 × 스킬배율 → 치명타 → 방어 `100/(100+def×(1-pierce))` → 속성/전달 배율 → 버프/상태 배율 → 장기전 증폭 → ±15% 난수. 독 등 지속 피해는 방어·속성 무시.
- 새 속성: `ELEMENT_DEFS`에 `wind: { name: '바람', color: '#b8f0d0' }` 추가 후 공격/스킬에 `element: 'wind'`.

```js
attack: { element: 'slash', delivery: 'ranged', pierce: 0.3 },
skills: [{ id: 'lanceCharge', name: '돌격 찌르기', cd: 8, element: 'slash', delivery: 'melee', pierce: 0.5, applies: [...] }],
resist: { slash: 0.85, fire: 1.25 },
statusResist: { all: 0.1, stun: 0.4 },
```

## 상태이상 저항
- 캐릭터 `statusResist: { all, <상태id> }` + 활성 버프의 `statusResist`(숫자 = 전체, 또는 객체) 합산, 최대 0.9.
- 부여 확률 ×(1−r), 지속시간 ×(1−r/2). 저항으로 막히면 '기절 저항' 같은 작은 글자 표시.
- 예: 탱커 철벽 방패 버프는 `statusResist: 0.6`.

## 상태이상 시스템 (`js/status.js`)
`STATUS_DEFS`에 상태를 데이터로 정의. 모든 상태는 지속시간이 끝나면 자동 해제(석화처럼 특수 해제는 콜백으로).

| id | 이름 | 효과 |
|---|---|---|
| poison | 독 | 0.5초마다 소량 피해 (`power`) |
| stun | 기절 | 이동·행동 불가 |
| confusion | 혼란 | 수시로 무작위 방향 전환, 공격 60% 오조준/헛손질 |
| weaken | 쇠약 | 주는 피해 x0.6 |
| petrify | 석화 | 이동·행동 불가, 피격 시 피해 x2.2 후 해제 |
| paralysis | 마비 | 약 1초마다 0.4초씩 굳음 |

부여 방법 (데이터만 수정):
```js
skills: [{ id: 'fireball', name: '화염구', cd: 8, applies: [{ status: 'weaken', duration: 4, chance: 1 }] }],
attackApplies: [{ status: 'poison', duration: 3, chance: 0.25, power: 5 }],   // 기본 공격 적중 시
```
스킬 코드에서는 `b.damage(u, e, amount, { applies: ap(slot) })` 또는 `b.applyList(u, e, list)` / `b.applyStatus(e, 'stun', 1.2, u)`.
부여 시 머리 위 아이콘(남은 시간 바), 스프라이트 덧칠/파티클, 하단 로그 '캐릭터명: 상태명' 자동 표시.

### 7번째 상태 추가 예 (화상)
```js
burn: { name: '화상', color: '#ff9a5a', tint: '#ff7a3a', tintA: 0.25, particle: '#ffb07a', tick: 0.4,
        onTick(u, b, s) { b.damage(s.src, u, s.power || 5, { dot: true, noCrit: true }); } },
```
사용 가능한 키: `name, color, tint, tintA, particle, blocksMove, blocksAct (bool 또는 (u,s)=>bool), dmgDealt, dmgTaken, spdMul, misdirect, tick+onTick, onApply, onUpdate, onExpire, onDamaged(→피해 배율), stack('refresh'|'ignore')`.
엔진은 `unit.blocked(키)`, `unit.smult(키)`, `unit.smax(키)`로 이 값들을 일반적으로 조회하므로 새 배율 키도 쉽게 추가 가능.

```js
sprite: 'assets/knight.png',                       // 단일 이미지 (프레임 1장)
// 또는 스프라이트 시트 (프레임을 가로 한 줄로 배치)
sprite: { src: 'assets/knight.png', frameW: 32, frameH: 32, frames: 2, fps: 6,
          scale: 1.5,            // 표시 배율 (생략 시 높이 ~54px에 맞는 0.5 단위 배율 자동: 16→3, 32→1.5, 64→1)
          // height: 54,         // scale 대신 표시 높이(px) 지정 가능
          foot: 1,               // 이미지 하단 투명 여백(px, 원본 기준) → 발 위치 보정
          portraitRect: [4, 0, 24, 24], // 초상화로 잘라낼 영역 (생략 시 첫 프레임 상단 중앙)
          pal: {...}, rows: {...} },    // (선택) 이미지 로드 실패 시 쓸 절차적 스프라이트 정의
portrait: 'assets/knight_face.png',   // (선택) 별도 초상화 이미지
```
- 기본 방향은 **오른쪽을 바라보는** 그림. 왼쪽은 자동 좌우 반전.
- 이동 중에는 프레임 순환, 정지 시 0번 프레임. 피격 흰색 번쩍임용 실루엣은 자동 생성.
- 최근접 이웃(nearest-neighbor) 스케일링. 캔버스 내부 해상도가 2배라 0.5 단위 배율도 선명.
- 이미지가 없거나 로드 실패 시 경고만 남기고 절차적 스프라이트로 폴백.
- 예시: `assets/example_knight.png` (32x32, 2프레임), `assets/example_knight_portrait.png`.
- file:// 로 열면 브라우저 보안상 PNG 초상화 자르기가 막힐 수 있으니 로컬 서버 사용 권장.

## 얼음 동굴 (`iceCave`)
- `ice: { traction, speedRef }`: 빙판 관성. 실제 이동 벡터 `u.v`가 목표 방향(dir×speed)으로 서서히 수렴하며, 수렴 속도 = traction × speedRef / 현재속도 (빠를수록 미끄러짐). 속도 크기는 일정 유지.
- `iceWalls: { segLen, hp, crackSpeed, hitCd }`: 외곽 벽을 구간으로 분할. 벽 방향 속도 ≥ crackSpeed(또는 돌진 중) 충돌 시 hp-1 → 균열 단계 표시, 0이면 크레바스. 크레바스 구간으로 벽을 넘으면 즉시 실격(`battle.fallen`, `simulate().fell`).

## 트램펄린 (`trampoline`) / 공중 상태
- `pads: [{ cx, cy, r, air, height, cd }]`: 밟으면 `u.air` 설정 → `u.airborne` true. 공중에선 유닛/공/건물/지형 충돌 없음, 착지 시 링 효과.
- 명중 판정 `Battle.hitCheck(src, tgt, o)` (damage() 진입 시):
  - 공중 대상: 근접(delivery 'melee') 항상 '회피', 원거리(delivery 'ranged') 항상 '명중'(혼란 오조준 무시, 투사체 유도).
  - 그 외: `evasion(tgt) - accuracy(src)` 확률로 회피. 현재 스텁(`st.eva`, `st.acc` 기본 0 → 항상 명중).
  - 향후 명중/회피 스탯은 STAT_DEFS/STAT_DEFAULTS에 `acc`, `eva`를 추가하면 바로 반영됨.
- `landShock: { r, stun, chance }`: 착지 시 충격파. 반경 내 지상의 상대는 넘어지며(옆으로 눕는 포즈) 기절(상태저항 적용), 기절이 끝나면 일어남.

## 타격 연출

- 공통 적중 문양은 일반 / 치명타 / 강타로 구분합니다. 베기는 방향성 검흔, 그 외 공격은 별 모양 충격과 파편 선으로 표시합니다. 지속 피해·반사·자해에는 추가 타격 문양을 적용하지 않습니다.
- 피격 시 스프라이트만 짧게 눌렸다 복원됩니다. 좌표·충돌 범위·공격 수치는 바꾸지 않습니다.
- `Battle.updateVisual(dt)`는 화면 프레임마다 실제 경과 시간으로 호출합니다 (`main.js`). `visualFx`와 피격 반동은 배속에 관계없이 같은 길이로 재생됩니다. 별도 실행 루프에서도 `update(dt)`와 함께 호출하세요.
- 동시 타격 문양은 최대 18개, 추가 카메라 반응은 최소 0.14초 간격입니다. 화면 흔들림은 최대 4px, 확대는 최대 8%로 제한하며 강한 확대를 약한 효과가 즉시 덮어쓰지 않습니다.
- 최종 KO는 짧은 배경 암전·승자 발광·K.O. 타이틀을 표시합니다. 결과 화면은 실제 시간으로 최소 0.9초 뒤에 열립니다. 팀원 한 명의 탈락과 엑조디아의 전용 승리 연출에는 이 효과를 적용하지 않습니다.
- 라인하르트 돌진에는 준비 자세와 모여드는 선, 이동 잔상, 벽 충돌 방향으로 퍼지는 파편과 먼지를 추가했습니다. 준비 시간과 피해량은 기존 값을 유지합니다.
- 충격파는 압력 띠·후속 링·밝은 선단·방사형 잔광으로 표현하며, 작은 링과 물결도 이중 파동으로 표시합니다. 중앙은 낮은 불투명도로 유지합니다.
- 공격 예고는 직선(흐르는 화살표·진행 띠), 원형(고정 외곽선·수렴 링·발동 게이지), 부채꼴(고정 외곽선·방사선·이동 파동)로 구분합니다. 진행도는 기존 예고 타이머를 따르며 범위와 지속시간은 바꾸지 않습니다.
- 무기·공격 디테일: 해머의 금속 면·그립·냉각 핀·추진 불꽃, 끝이 가늘어지는 참격과 후속 검흔, 화살의 촉·축·깃, 화염파의 움직이는 꼬리, 마법탄의 속성 색·회전 무늬, 브로리 기탄의 에너지층을 절차적으로 그립니다. 속도·피해량·충돌 반경은 유지하며 마법탄의 잔광과 적중·건물 충돌 파편도 같은 속성 색을 사용합니다.
- 화염 강타는 오버워치 라인하르트의 화염 강타를 참고한 세로형 화염 참격입니다. 길고 뾰족한 화염 막·백색에 가까운 노란 중심·주황색 외곽·짧은 열기 잔상으로 표현합니다. 비행 중 자세는 유지하며 가장자리와 내부의 결만 일렁입니다. 발사 섬광도 진행 방향에 수직인 참격으로 맞췄습니다.

## 대사 시스템
캐릭터 정의에 `lines` 추가 (없으면 기존 '캐릭터명: 스킬명' 로그):
```js
lines: {
  skill: { '스킬 표시 이름': ['대사1', '대사2'] },      // 스킬 시전 시 로그: 이름: "대사" [스킬명 태그]
  event: { battleStart: [...], win: [...], ... },        // 이벤트 대사 (로그 + 머리 위 말풍선)
  cd: { lowHp: 10 },                                       // (선택) 이벤트별 쿨다운 초. 기본 6초, 스킬 0초
}
```
- 무작위 선택(직전과 같은 대사 회피), 캐릭터당 대사 간 최소 1.2초. battleStart/win/lose/fallCrevasse는 쿨다운 무시. 대사는 하단 로그에만 표시(말풍선 없음). 대사가 없는 이벤트는 아무것도 표시하지 않음.
- 범용 이벤트: battleStart, buffed(버프 획득), debuffed(해로운 상태이상: 기절/넘어짐/제압/독 등 — `STATUS_DEFS`에 `positive: true`면 제외), healed(회복), barrierHit(방벽 피격), lowHp, kill/win, lose.
- 상황 이벤트(대사 지정 시 사용): wallSlam, chargeMiss, pinned(붙잡음), pinnedBySomeone, stunned, knockedDown, barrierBroken, fallCrevasse, airborne, water. (라인하르트는 붙잡힘/기절/넘어짐을 debuffed 하나로 처리)
- 새 이벤트: 코드에서 `battle.say(unit, '키')` 호출.

## 스프라이트 방향 (격투게임식)
- 상대보다 위(y가 작음)에 있으면 앞모습, 아래면 뒷모습 (데드존 10px). 좌우는 상대 쪽을 바라보도록 반전 (데드존 8px, 행동 불가 중엔 유지).
- `sprite.faces: { front: 'left'|'right', back: 'left'|'right' }` = 원본 그림이 바라보는 방향. 없으면 'right'로 가정(절차적 스프라이트). 잔상/넘어짐/해머/와이어도 같은 기준(`spriteSX`)을 사용.
- 판정: 라인하르트 front=left, back=right / 이블린 front=left, back=left.

## 직접 플레이 모드 (`js/direct.js`)
- 스테이지 선택 화면의 **직접 플레이 모드** 토글(경기 집중 모드 아래, 마우스 올리기/길게 누르기로 설명). 켜면 플레이어 = P1(블루 팀, 0번 팀 첫 캐릭터). A·B 타입 모두. 저장: localStorage `psDirectMode`.
- 제외: 농구장(`basket`)·야구장(`baseball`)·탈출맵 → 일반 시점 (카드에 '일반 시점' 표시, 하단 바 ` · 일반 시점`). 리플레이·영상 저장 재생도 일반 시점.
- 조작: 로그·버튼 밖 아무 곳 클릭/탭 = 진행 방향 반전 (쿨타임 0.45초). 반전 뒤 0.5초(`FLIP_HOLD`, game.js) 동안 AI 가 방향을 되돌리지 못함 (벽·충돌 튕김 `u.bnc` 는 그대로 적용). 스킬은 자동.
  - 반전은 시뮬 스텝 사이에 적용되고 리플레이에 `inp: [[스텝, 유닛 번호]]` 로 기록 → 리플레이 재생 때 같은 스텝에 다시 적용.
- 시점: three.js 없이 캔버스 2D 원근 계산. 바닥 = `Render.draw(ctx, b, { v3d: true })` 로 그린 2D 전장(스테이지·기믹·이펙트·투사체)을 원근으로 눕혀 가로 띠·칸 단위 아핀 변환으로 그림. 경기장 테두리 = 벽, 기본 건물 = 3D 상자, 캐릭터·소환수 = `Render.drawUnit` 그림을 세운 판(멀리→가까이 정렬), 투사체 = 바닥 그림 + 공중 빛 구슬.
  - 카메라: 내 캐릭터 뒤 어깨 너머(거리 100·높이 80·옆 22). 상대는 자연스럽게(이징) 카메라 쪽으로 돌아봄. 내 캐릭터는 뒷모습.
  - 회전 입력이 없으면 0.7초 뒤부터 시점이 천천히 상대 쪽으로 돌아감. 상대가 화면 밖이면 가장자리 화살표.
  - PC: 마우스 잠금(Pointer Lock) + 마우스 이동 = 시점 회전. **스페이스를 누르는 동안 잠금 해제**(배속 버튼 등 클릭, 이때 클릭은 반전 안 함), 떼거나 다음 클릭에 다시 잠금.
  - 모바일: 자이로(처음 직접 플레이 때 '자이로를 켤까요?' 한 번 물어봄, iOS 는 그 탭 안에서 권한 요청, 선택은 설정에 저장).
- 세워 그리기: 특수 건물(트랭크스 냉장고 등 `bl.draw`)·x 가 있는 스테이지 물체(`sortItems` 항목에 `x` → 인형뽑기 인형·스네이크 꼬리)는 각자 작은 캔버스에 그려 발 위치에 세움. 위층 그림(`drawOver`·`drawTop` 훅, 위층 이펙트, 입자 = `Render.draw` 의 `o.lift`)은 캐릭터마다 몸 둘레 칸(가까운 캐릭터끼리 나눔)을 잘라 그 캐릭터와 같은 배율·발 위치로 세우고, 칸 밖은 바닥에 눕힘 (픽셀을 읽지 않음 → file:// 에서도 동작).
- 투사체: 그 캐릭터의 투사체 그림(`Render.drawProj`)을 높이 16 공중에 세우고, 진행 방향은 화면에 비친 방향으로 돌림 + 바닥 그림자.
- 근접 휘두르기(실험): 무기 그림과 호 궤적을 손 높이의 수평면에 눕혀 그림 (`Render.swingPose`, 박치기는 기존처럼 세움).
- 큰 이펙트: 이펙트·훅(`drawOver`·`drawTop`)마다 그리기 명령 좌표로 범위를 재서(픽셀은 읽지 않음) 92×112 를 넘으면 다음 프레임부터 전용 캔버스(최대 4개, 넘치면 위층)에 그리고, 그 프레임에 잰 범위만 잘라 **세운 판**으로 그림: 가운데 = 캐릭터 허리 높이(24), 위치 = 이펙트에 걸친 가까운 캐릭터 발(없으면 이펙트 가운데), 칸 자르기 없음 (`Render.draw` 의 `o.route`). 작은 이펙트는 캐릭터 칸에 세움.
- 캐릭터 그림을 제자리에: 그리는 동안 `b._v3d` 도구가 있음 (`js/direct.js` V3D) → `stand({x,y,z?,w,h,draw,maxS?})` 세운 판(z = 떠 있는 높이), `floor(draw)` 바닥, `flat({x,y,z,r,draw,sy?})` 높이 z 의 수평면(도는 원반 등), `beam({x1,y1,x2,y2,z|z1,z2,w,draw(c,L)})` 두 점 사이 3D 띠(광선·줄), `wall({x1,y1,x2,y2,h,draw(c,L)})` 바닥에 고정된 세로 판, `box({x0..z1,col})` 3D 상자, `shadow(x,y,r)`. 여기로 넘긴 그림은 큰 이펙트 잡기에서 빠짐.
  - 공용 이펙트: 충격파·고리(shock/ring) = 바닥, 기둥·운석·번개 = 세움, 궤적(streak) = 몸 높이(18) 3D 띠, BattleVFX 폭발·불꽃 = 하나씩 세움. 맞은 자리 이펙트(impact·glow·crescent·slash·wallDust)는 큰 이펙트 판(가까운 캐릭터 허리 높이)으로 남음.
  - 캐릭터별: 블레이드 스플릿 블레이드 큰 칼날 = 높이 8 에 뜬 수평 회전 원반 + 그림자 / 카이바 광선·백룡 광선·XYZ 캐논 = 높이 26 3D 띠, 충전·끝점 폭발 세움 / 듀얼 주먹·엑조디아·실크햇 세움, 자석 줄 3D 띠 / 구울즈 등장 몬스터(높이 z)·백은성 세움, 물결 바닥, 시간 정지 회색조 없음 / 신비술사 구슬 세움, 조종 실 3D 띠 / 공용 스킬(skills2) 백스텝 화살표·기도 원 바닥, 텔레포트 기둥·마법구 세움 / 갈포드 포피(떨어짐·점프) 세움 + 그림자 / 브로리 하트·어색한 침묵 = 두 캐릭터 사이에 세움 / 루델리안 불꽃 세움, 섬광 원 바닥, 눈 광선 3D 띠 / 슈르프 더스트 토네이도 바닥, 드래곤 브레스 3D 띠 / 라미아 팔 세움, 조준선·광선·명령 줄 3D 띠 / 미츄헨 도끼 세움 + 그림자, 전자기장 선 3D 띠, 도탄 세움 / 베르제브트 빨려드는 물건·분신 세움 / 샌즈 뼈 줄 = 바닥에 고정된 세로 판, 블래스터 머리뼈 세움 + 광선 3D 띠 / 육군보병 수류탄 세움 + 그림자, 조준선 3D 띠 / 오쿠야스 공간 삭제 범위 바닥, 더 핸드 세움 / 죠스케 크레이지 다이아몬드·러쉬, 죠나단·디오 캐릭터 표시 = 캐릭터마다 발 위치에 세움 / 죠나단 스피드왜건 세움, 모자 톱 = 높이 16 수평 원반 / 아오오니 떨어지는 상자 = 3D 상자, 옷장 어둠 바닥(방 이동 밀기 없음) / 잭오 불씨·호박 폭탄 세움.
- 훅이 세울 물체(이전 방식, 계속 지원): 직접 플레이 그리기 중에는 `b._v3dStand` 목록이 있음 → 훅이 `{ x, y, w?, h?, draw(ctx) }` 를 넣으면 그 자리에 세워 그림 (듀얼 몬스터 정령·카이바 몬스터 그림, 축구공, 듀얼리스트 카드 사용 UI(최근 3장 + 이름, 시전자 머리 위에 층층이, 가까워도 1.5배까지만)가 사용). 선택 `maxS` = 최대 배율.
- 스테이지별: 풀장 공 = 바닥 그림자 + 공중 높이의 구, 축구장 = 공 세움 + 골대(흰 기둥·크로스바·반투명 골망) 3D, 인형뽑기 = 크레인 구조(모서리 기둥·높이 150 옆 레일·갠트리·트롤리·케이블)는 벽처럼 고정된 3D 상자, **집게만** 카메라를 바라봄 (유리 반사광·GET 글자 생략, 바닥 그림자는 유지). 인형은 스프라이트 크기만큼 캔버스를 잡아 잘리지 않음.
- 스테이지 장식 세우기(t247u): 스트리트 파이트 = 울타리 철망 세로 벽(높이 26) + 기둥 3D 상자, 관객 세운 판 + 그림자 / 패스트푸드점 = 메뉴판 세로 벽 + 카운터 3D 상자, 손님 세운 판(말풍선 포함) / 수업 중의 교실 = 선생님·학생 세운 판, 교탁·책상 3D 상자 / 바베큐 불판 = 거대한 손을 고기 위 제자리에 위에서 내려오게 세움 + 불판 그림자 / 갈포드 분신 세움. 세운 장식은 바닥 그림에서 빠짐(중복 없음). 카메라 바로 앞 세운 판은 흐리게.
- 화면 안내: `b._v3d.hud(fn)` = 카메라 화면 좌표에 그림 (축구장 점수판·골 안내, 교실 '얼음!' 안내).
- 뱀꼬리 맵: 외곽 벽 없이 바닥 그림을 경기장 크기로 사방 반복 + 먼 곳 안개 (끝없는 맵처럼 보이게, 시뮬 경계는 그대로).
- 위아래 시점(마우스·자이로): 올려다보기는 내 캐릭터 상반신이 화면에 남는 만큼만(`userPitch` ≥ −0.38 → 최종 기울기 0.07rad), 내려다보기 +0.32.
- 평면으로 남는 것: `drawUnder` 훅 그림(스테이지 바닥 장치), 바닥 이펙트, 캐릭터 칸 밖의 위층 이펙트, x 가 없는 `sortItems`. 처음 커지는 프레임은 한 번 세워 보일 수 있음. 시간 정지 흑백 효과 없음.
- 그리기·카메라는 전투 상태를 바꾸지 않고 시뮬 난수를 쓰지 않음.

## 설정 (`js/settings.js`)
- 메인 화면 ⚙ 설정 버튼. 항목: 자이로 켜기(모바일), 자이로 감도, 마우스 감도. localStorage `psweb.settings`.
- 항목 추가: `Settings.define({ key, type: 'toggle'|'range', label, desc, def, min, max, step, request })` (toggle 의 `request()` = 켤 때 권한 요청 Promise). 값: `Settings.get(key)`, 변경 알림: `Settings.on(key, fn)`.

## 뒷모습 스프라이트 (`js/sprites_back.js`)
- `BACK_SPRITES[id] = { pal?, rows: [16줄 x 16칸] }` → sprites.js 가 `s.back` 을 만들어 PNG 뒷모습과 같은 경로로 사용(직접 플레이 내 캐릭터·야구 포수). 캐릭터 정의의 `backRows`/`backPal` 로도 지정 가능.
- 있음: swordsman, archer, mage, tank, assassin, lancer, priest, berserker, okuyasu, josuke, jonathan, dio, trunks. 없는 캐릭터는 기존 방식(앞모습 그림) 그대로.

## 신규 스테이지 (STAGE_HOOKS)
스테이지 특수 규칙은 `js/stages2.js`의 `STAGE_HOOKS`(init/step/clamp/noClamp/floor/drawUnder/drawOver)로 구현. 결과 문구는 `battle.resultText`, 종료 유형은 `battle.endType`(ko/lap/train/trainDraw/timeout).

### 레이싱 코스 (`race`)
- 타원형 링 트랙. 잔디(안쪽·바깥)도 이동 가능하나 이동속도 ×0.8(`grassSpd`), 벽은 경기장 외곽뿐. 상단 체커 라인이 출발/결승선.
- **시계방향 1바퀴 완주 시 체력과 무관하게 승리** → `(이름) 완주! 승리!`. KO도 유효.
- 부정 방지: 중심 기준 각도로 나눈 8개 섹터를 시계 방향 순서대로 통과 + 누적 각도(역주행 차감) ≥ 360°. 도로 안쪽 −약 40px(`minR`)까지 잔디에서도 진행 집계, 그보다 안쪽에선 정지·중앙 가로지르기로 섹터 점프 불가. 중앙 전광판(`board`)은 벽.
- 미니 트랙 UI + HP바 아래 체커 진행 바로 진행도 표시. 조향 보조 없음(벽 반사 랜덤성 `bounceRnd`, 적 방향 기울기 `tiltMax`로 조절).

### 지하철역 (`subway`)
- 상·하단 승강장, 가운데 선로. 문 4개(위 2·아래 2, 같은 x에 대칭, 폭 68px), 창문은 문을 피해 자동 배치(`winW`/`winGap`). 경고(신호등·선로 은은한 발광·로그) → 고속 진입 후 감속 → 정차(양쪽 문 열림) → 문 닫힘 안내(`exitHint`, 밖에서 탑승 불가·탑승자는 문 쪽으로 향함) → 천천히 가속하며 출발.
- 움직이는 열차에 치이면 회전하며 날아가 소량 피해 후 안전한 승강장에 착지.
- 창문은 파괴 가능(균열 단계), 깨진 창은 출입구. 가속 중에도 깨진 창으로 탈출 가능.
- 열차가 화면을 벗어날 때 안에 있으면 `(이름) 지하철에 실려 탈락! (상대) 승리!`. **둘 다 안에 있으면 체력 비율이 높은 쪽 승리.**
- 열차가 없을 땐 선로도 일반 바닥. 벽은 원-선분 충돌로 끼임 없음.

- 트램펄린: 쿨다운 없음(`cd: 0`) — 착지 후 패드에 닿아 있으면 즉시 다시 튐.

### 공사 타워 (`tower`, js/stages3.js)
- 좌상단·우하단에 버튼, 중앙에 해치. 버튼(반경 18)을 밟으면 **항상** 해치 개방. 재작동은 해치가 닫힌 뒤 `btnCd` 1.5초 후부터.
- 해치 위에 있던 캐릭터는 추락 탈락 → `(이름) 해치로 추락! (상대) 승리!`. 공중/회피 무적 중이면 버팀.
- 해치가 조금이라도 열리면(`wallAt`) 양쪽 모두에게 벽 → `holdT` 2.5초 후 닫히고 다시 통행 가능.

### 스트리트 파이트 (`street`, js/stages3.js)
- 중앙 철망 링(맵의 약 37% 넓이)에서 시작. 철망은 변별 칸(`segsX`/`segsY`)마다 내구도(`segHp`): 부딪힘·돌진·투사체로 균열 → 뚫리면 바깥 관중석으로 나갈 수 있음.
- 관중 = 싸우는 두 캐릭터를 제외한 캐릭터 스프라이트(중복 허용, 전투 때와 같은 크기·충돌 반경), 살짝 흔들거림. 관중에 부딪히면 캐릭터는 튕기기만(피해 없음), 관중은 회전하며 날아가 사라짐.

### 아이돌 무대 (`idol`, js/stages4.js)
- 위쪽 무대 뒷벽(대형 스크린 3개) ~ 아래 관객석 사이의 무대에서만 싸움. 이동 가능 영역 `b.play`가 무대로 좁혀져(뒷벽·관객석은 경기장 밖 취급) 이동·벽 반사·돌진·넉백·순간이동·끌어오기 등 `clampPos`/`bounceWalls`를 쓰는 모든 이동이 무대 가장자리에서 끝남. 추가로 매 스텝 안전장치(`safeClamp`)가 영역 밖 캐릭터를 안으로 되돌림. 관객은 맞지도, 날아가지도 않음.
- 관객 = 싸우는 두 캐릭터를 제외한 모든 캐릭터(중복 허용, 전투 크기 그대로), 무대를 바라보는 **뒷모습**(`sprite.back`; 없는 절차적 캐릭터는 정면 스프라이트의 머리 부분을 머리색(`pal.H`)으로 덮어 뒷모습 표현). 느린 들썩임 + 일부 응원봉(은은하게 흔들림), 팬심 획득 직후 잠깐 더 신나게.
- **스포트라이트**: 반경 40, 한 번에 하나, 무작위 위치(캐릭터에서 60px 이상 떨어진 곳 우선). 첫 등장 2.5초, 획득 후 3.5초 뒤 다음 등장, 8초 동안 아무도 안 밟으면 사라지고 1.2초 뒤 재등장. 먼저 밟은(공중 제외) 쪽 **팬심 +1** → 로그 `(이름): 팬심 획득! (n)`.
- **팬심 리드 버프** (리드 중일 때 고정, 동점이면 해제): 주는 피해 ×1.3, 이동속도 ×1.2, 공격속도 ×1.15 (`nodispel` 버프 `fanLead`). 버프 `dmgDealt` 배율은 game.js 피해 계산에 새로 반영.
- 관객은 최상단 레이어(새 훅 `drawTop`: 캐릭터·이펙트 위, 피해 숫자/말풍선 아래)에 그려서 무대 앞쪽 캐릭터는 관객 뒤에 있는 것처럼 보임.
- 중앙 스크린 = **실시간 중계**: 매 프레임 실제 화면(관객 그리기 전)에서 리드 캐릭터 주변(폭 175px)을 오프스크린 버퍼로 잘라 확대 표시, 카메라는 부드럽게 따라감(lerp). 캡처 영역은 스크린 벽 아래로 제한 → 재귀 피드백 없음. 동점이면 무대 전체 와이드 샷 + IDOL STAGE. LIVE 태그(깜빡이는 빨간 점), 팀 색 테두리, 아주 옅은 주사선. 좌우 스크린에 양쪽 팬심 수와 LEAD 표시.

### 다이빙 존 (`diving`, js/stages4.js)
- 수영장이 위·왼쪽 끝까지 차지(데크 타일은 아래쪽만), 오른쪽 위 기둥 전체가 다이빙 구역(플랫폼+계단, 폭 92). 다이빙대는 두꺼운 판 + 물속 지지대 2개 + 대각 브래킷 + 볼트 고정부. 무인도와 같은 물 지형(감속 0.6, 산소, 전기 ×1.4 등, 물보라/파문). 오리(`waterproof`)는 그대로 면역.
- 오른쪽 위 **계단**: 아래쪽(노란 띠) 입구로 위를 향해 들어올 때만 진입, 옆면/윗면은 벽(입구 앞(노란 띠 폭)은 막지 않음, 밀어낼 땐 왼쪽 또는 입구 아래로만 — 경기장 벽에 끼지 않음, `clampPos` 훅 + 매 스텝 안전장치). 계단 안에선 자동으로 오름(이동속도×0.55, 40~90px/s) → 위 플랫폼 → 다이빙대 끝.
  - 오르는 중 피해를 받으면 45px, 둘 다 계단에 있을 때 부딪히면 아래쪽이 70px 밀려 내려감. 입구 아래로 밀리면 밖으로 튕겨 나옴('미끄러짐!'). 기절 중엔 멈춤. 계단 위에서도 공격은 가능.
- 다이빙대 끝 도달 → 자동 공중 상태로 다이빙(1.1초, 착지점은 수영장 안 무작위, 낙하 지점 원 표시). 착지 시 큰 물보라.
- 착지 순간 상대가 수영장 안(지상)에 있으면: 가장 가까운 수영장 밖(계단 제외)으로 튕겨 내고 **2.5초 넘어짐 기절**(기존 `knockdown`, 상태 저항 적용).

## 태도 귀무사 (`kidomusha`, js/kidomusha.js)
- 근접 태도(베기). 스프라이트: `assets/oni/` (front/back, 오니화 oni_front/oni_back, portrait/oni_portrait). 대사 없음(`lines: {}`).
- **오니화 게이지(패시브)**: 적중(`dealt`)·피격(`damaged`) 시 충전(HP 아래 바). 가득 차면 오니화 → 스프라이트/초상화 교체, 게이지 초당 `drain` 감소, 0이 될 때까지 충전 불가 후 복귀.
  - 오니화 중: 모든 공격이 `echoDelay` 간격으로 2회(2타는 `echoMult` 배율), 적중마다 자해(`selfK`, 최소 `selfMin`, HP 1 미만으로는 안 떨어짐).
- **혼령**: 게이지 25 소모(오니화 중 사용 불가). 짧게(1~1.6초)/길게(2.8~3.8초) 무작위. 몸 충돌 없음(통과), 공격은 서로 가능. 종료 시 근처 상대를 베고 공중에 띄움.
- **고스트 온**: 상대가 공중일 때만. **첫 일격만 유도**해 베고(상대는 곧 착지해 정상 행동), 상대 주위를 한 바퀴(경기장 중앙 쪽 방향) → `trackChance` 50%: 추적 후속타(붉은 궤적, 적중 시 카운트) / 50%: 무작위 방향으로 튕겨 나가 일반 핀볼 이동(적 방향 보정 없음). `window` 1.2초 안에 실제 몸통 충돌이 나면 카운트 +1 후 다시 회전, 못 하면 '연계 끊김'. 6회 성공 시 X자 대참격(공중 대상 적중 허용: `airHit`).
- 범용 확장: 액션 객체에 `step(dt)`가 있으면 game.js가 그대로 실행(캐릭터 파일에서 커스텀 액션 정의).

## 브로리 (2인 1팀: 파라가스 + 브로리)
선택 화면에서 **브로리**를 고르면 한 팀에 파라가스와 브로리가 함께 출전합니다. 그 팀은 두 명이 모두 쓰러져야 패배합니다.

### 엔진 확장 (다인원)
- `Unit(def, team, slot, n)`: 2인 팀은 스폰 위치를 y ±34, x ±14만큼 벌립니다. 모든 유닛에 `gender`('male'/'female')가 있습니다.
- `b.enemy(u)`: 가장 가까운 생존 적을 고릅니다. 표적이 자주 바뀌지 않도록 0.75 히스테리시스를 둡니다. 1v1에서는 기존과 똑같이 상대 1명을 반환합니다.
- 아군끼리는 서로 튕겨나기만 합니다. 충돌 피해와 onHit/onHurt 훅은 발동하지 않고, 효과음은 bump만 납니다.
- HUD: 2인 팀은 이름·수치·작은 HP바를 두 줄로 보여 주고, 쓰러진 유닛의 줄은 흐리게 표시합니다. 초상화는 브로리이며 LSS가 되면 바뀝니다.
- 스테이지 처리: RACE는 팀·슬롯별 위치 오프셋을 씁니다. SUB는 한 팀이 모두 이탈해야 패배합니다. TOWER에서 버튼을 누른 유닛이 자기 팀원을 떨어뜨리면 상대 팀이 이깁니다. IDOL 팬심은 팀 단위로 계산하고 버프는 팀원 전원에게 줍니다. DIVE의 계단 충돌과 착수 파동은 모든 적에게 적용됩니다. 신비술사 구슬·제어는 다수의 적을 처리합니다.
- 브로리 vs 브로리 미러(4인)도 허용합니다. 로그 이름에 (P1)/(P2)가 붙습니다.

## 듀얼리스트 ("어둠의 유희") — `js/duel.js`, `js/cards.js`
카드로 싸우는 캐릭터 프레임워크. 지금 들어 있는 카드(`T_` id)와 캐릭터 **듀얼리스트 (테스트)** 는 모두 **임시 테스트용**이며 실제 카드 디자인으로 교체할 자리입니다.

### 규칙
1. **LP 4000 고정** (`DUEL.CFG.LP`). 카드로 LP 지불(`ctx.payLp`)·회복(`ctx.heal`) 가능.
2. **턴 루프**: `드로우!` → 메인(상황에 따라 카드 0~2장 사용, 몬스터 효과는 턴당 1회) → **대기**(상대에게 피격되거나 상대가 스킬/카드를 쓸 때까지) → 반복. 로그에 `드로우! 패 n · 덱 m`, `[몬스터 7] 카드명`, `카드를 1장 세트 함정 2/3`, `함정 발동!` 표시. 카드 사용 시 머리 위에 작은 카드 팝업(앞면/세트는 뒷면) + 카드명.
   - 타이밍: 첫 드로우 1.0초, 드로우→메인 0.4초, 연속 사용 간격 0.65초, 대기 최소 1.0초(연타로 턴 폭주 방지), 상대가 아무것도 안 하면 6초 후 다음 턴(안전장치). 기절 등 행동 불가 중엔 턴 진행 정지, 봉인 중엔 드로우만 하고 카드 사용 불가.
3. **덱 40장**. 덱 0장에서 드로우(턴 드로우·카드 효과 드로우 모두) = **즉시 패배** (`덱 아웃!`, 결과 창 "○○ 덱 아웃! △△ 승리!", `battle.endType = 'deckout'`).
4. 사용한 카드·릴리스한 카드는 즉시 **묘지**.
5. 몬스터: Lv≤4 자유 / Lv5~6 패의 다른 몬스터 1장 릴리스 / Lv7~8 2장 / Lv9+ 3장.
6. 함정: 최대 3장 세트(뒷면). 세트 1장당 이동속도 ×0.88, **3장이면 마법 사용 불가**(함정이 발동해 칸이 비면 해제). 세트 직후 0.6초는 발동 불가.
7. 시작 패 5장. 패 0장 페널티 없음.

### 피해 스케일
- **받는 피해**: 듀얼리스트가 받는 모든 피해 ×`LP_SCALE`(=4000/870≈4.6). 즉 LP 4000 ≈ 일반 캐릭터 HP 870의 생존력이고, 숫자만 유희왕처럼 크게 보입니다 (예: 검사의 40 피해 → 약 184 LP). 듀얼리스트끼리도 같은 규칙. 지속 피해·건물/벽 피해 포함 `Battle.damage` 를 거치는 모든 피해에 적용. LP 지불/회복은 LP 단위 그대로.
- **주는 피해**: 카드 ATK × `ATK_SCALE`(0.035) × 효과 배율. ATK 1800 → 63, ATK 3500 → 122 (일반 캐릭터 스킬 한 방 수준). 마법/함정의 "2000 상당 피해"는 `ctx.val(2000)` = 70.
- 조절: `DUEL.CFG.LP_SCALE`, `DUEL.CFG.ATK_SCALE` (js/duel.js 상단).

### 카드 정의 형식 (`js/cards.js`)
```js
{ id: 'T_M06', name: '화염 비룡', type: 'monster', level: 6, atk: 2400, def: 1700, element: 'fire',
  text: '[릴리스 1] 화염 브레스 + 3초간 비룡의 혼 지원', lines: ['날아올라라, 화염 비룡!'],
  effect(ctx) { ctx.fan(ctx.atk(1.0), { range: 170, spread: 0.7 }); ctx.summon({ dur: 3, rate: 1, mult: 0.35 }); },
  ai: { tags: ['damage'], range: 170, dmg: 1.7, priority: 8 } },
{ id: 'T_T02', name: '스킬 봉인의 함정', type: 'trap',
  trigger: { on: 'oppSkill', when: (ctx, ev) => true },          // 발동 조건
  effect(ctx, ev) { ctx.negate(); ctx.status(ev.src, 'seal', 3); }, // negate() = 상대 스킬/공격/카드 무효
  ai: { priority: 8 } },
```
덱: `{ 카드id: 장수 }` 또는 id 배열(40장). 캐릭터 정의에 `duelist: { deck: MY_DECK }` 만 넣으면 듀얼리스트가 됩니다(HP는 자동 4000).

**함정 조건 `trigger.on`**: `oppAttack`(상대 기본 공격 시작, 무효 가능) · `oppSkill`(상대 스킬 또는 카드 사용, 무효 가능) · `damaged`(피격 직후) · `projectile`(상대 투사체가 85px 안으로 접근) · `lowLp`(매 프레임, `when` 으로 기준) · `oppDash`(상대 돌진 접근) · `oppAirborne`. `when(ctx, ev)` 로 세부 조건, `ev.src` = 상대 유닛. 이벤트 하나에 함정은 1장만 발동.

| 정보 | `ctx.u`(나) `ctx.e`(현재 상대) `ctx.foes()` `ctx.b`(Battle) `ctx.card` `ctx.S()`(상황 객체) `ctx.mult`(소생 배율) |

### 카드 AI (`DUEL.AI`)
메인 단계마다 패의 각 카드(같은 id는 1번)에 대해 **사용 가능 여부 → 점수**를 계산해 최고점 1장을 사용, 최고점이 `PLAY_MIN`(14) 미만이면 **보류**(패 7장 이상이면 기준 0, 덱 3장 이하면 −6).
- 상황 객체 `S`: 양측 HP(`myHpR`, `oppTargetEff` 등 게임 피해 기준 남은 체력), 거리 `d`, 상대 공중/기절/시전·돌진 중, 접근 중인 투사체 수 `incoming`, 상대 스킬 쿨 `oppSkillSoon`(가장 빨리 준비되는 스킬까지 초; 상대가 듀얼리스트면 턴 단계로 추정), 근/원거리, 상대 세트 카드 수, 덱/패/함정 수, 마법 봉쇄, 묘지 몬스터/마법 수·최고 ATK, 봉인 여부, 다인 팀 여부.
- 태그 평가(`AI.evaluators`): `damage`(예상 피해×방어 보정 + 남은 체력 대비 비율, 막타 +60, 기절 상대 +, 근접 카드는 공중 상대 불가, 덱이 적으면 공격적), `heal`(낭비면 −60, 위급할수록 +), `draw`(덱−n < 4 면 금지, 덱이 줄수록·패가 많을수록 −), `defense`(투사체·곧 쓸 상대 스킬·시전 중이면 +, 같은 버프 중복 금지), `control`(기절 중이면 −, 시전 중이면 +).
- 공통 규칙(`AI.rules`): LP 비용(지불 불가면 금지, 저체력일수록 큰 감점), 상대 세트 카드가 있을 때 큰 릴리스 투자 감점.
- 함정 세트(`AI.trapValue`): 조건이 일어날 가능성(상대 스킬 유무/쿨, 근접·원거리), 세트 수에 따른 감속 감점, 같은 함정 중복 감점, 3장째 세트로 쓸 만한 마법이 막히면 감점.
- 릴리스: 대상 레벨보다 낮은 몬스터 중 보존 가치(`keepValue` = 레벨·`ai.keep`·지금 쓸 때의 점수)가 낮은 것부터 고르고, 그 가치 합(패 6장 이상이면 ×0.6, 아니면 ×0.85)을 점수에서 뺌 → 큰 몬스터가 그만한 가치가 있을 때만 소환.
- 사거리(`ai.range`) 밖이면 보류(다음 턴으로 홀드). `ai.when` 이 false 여도 보류.
- 확장: 카드별 `ai.score(S, ctx)` / `ai.when`, 새 태그 `DUEL.AI.evaluators.태그 = (card, S, ai) => 점수`, 전역 규칙 `DUEL.AI.rules.push((card, S, ai, plan) => 가산)`. 디버그: `unit.duel.lastEval` 에 마지막 평가 상위 4개.

### 패 한도 7장
- 턴 드로우 시 패가 7장 이상이면 드로우 전에 1장을 줄임: 빈 슬롯이 있고 쓸만한 함정이 있으면 세트, 아니면 가장 가치 낮은 카드를 묘지로 (로그: "패가 가득! <카드> 를 묘지로").
- 마법은 세트 개념이 없으므로 버림 대상으로만 처리.
- 엑조디아 부위는 패가 부위뿐일 때만 버림. 묘지 시너지(블랙 매지션 걸, 죽은 자의 소생/리빙데드, 탐욕의 항아리)가 있으면 해당 몬스터를 먼저 버림.
- 카드 효과 드로우(욕망의 항아리 등)는 예외로 7장을 넘을 수 있음. 패 6장 이상이면 AI의 카드 사용 기준이 낮아짐.

### 캐릭터를 상단 UI 앞에 그리기
- 상단 UI(`#hud`)는 DOM이라 높이 뜬 캐릭터가 가려졌음 → `#hud` 바로 다음에 투명 오버레이 캔버스 `#cvTop`(클릭 통과)을 두고, 매 프레임 `Render.drawTopUnits`가 상단 UI 영역(높이 = `#hud` 높이)에 걸친 유닛만 같은 카메라(줌·흔들림)로 다시 그림.
- UI 영역으로 클립하므로 같은 자리 픽셀만 덮어 이중으로 보이지 않음. 그림자·팀 링·분노 광채는 오버레이에서 제외(그림자는 땅에 그대로). 이펙트·스테이지 물체는 기존 순서 유지.
- 듀얼리스트 소환 몬스터도 포함: 훅 `drawAboveUI(ctx, b)`(duel.js: 몬스터 혼·크리보, kaiba.js: 점프 몬스터·YZ 드래곤·환영·블루 걸)로 **몸체 스프라이트만** 그림. 카드 팝업·카드 이름·외침·발밑 광채·광선/이펙트·엑조디아 연출은 상단 UI 뒤 그대로.

## 동영상 저장 (MP4 / webm, 효과음 포함)
- 리플레이 뷰어 → **저장** → "🎬 동영상 저장": **★ 하이라이트 / A~B / 전체**. 실시간으로 재생하면서 녹화합니다(하이라이트는 "최고의 플레이" 배너 포함). 화면 아래 빨간 막대가 진행률이고, **취소**로 중단할 수 있습니다. 끝나면 `PS_..._동영상_....mp4`(또는 `.webm`) 파일이 다운로드됩니다(720x1280, 30fps).
- 형식: `MediaRecorder.isTypeSupported` 로 MP4(`avc1.42E01E,mp4a.40.2` → `avc1,opus` → `video/mp4`)를 먼저 고르고, 안 되면 webm(vp9/vp8 + opus, 길이 정보 추가). 저장 메뉴 제목 옆 "형식: MP4/WEBM" 이 실제 형식. 최근 Chrome/Edge(약 126+)는 MP4(H.264+Opus), Firefox 등은 webm.
- 소리: "소리 포함"(기본 켬). 게임 효과음(벽/충돌, 새 소리 없음)의 WebAudio 압축기 출력을 `MediaStreamAudioDestinationNode` 로도 보내 캔버스 스트림에 오디오 트랙으로 추가. 실시간 재생 중 나는 소리만 들어가고, 빨리감기(탐색) 중 소리는 막음. 리플레이는 스피커가 꺼진 상태라 녹화 중에도 스피커로는 안 나옴.
- 영상에는 게임 화면 그대로 들어갑니다: 전장 + 상단 UI(체력/패/덱) + 상단 UI 위 캐릭터 + 하단 로그 + 배너. 리플레이 조작 버튼은 들어가지 않습니다.

### 왜 그림 사본이 필요한가 / 그림을 바꿨을 때
- 크롬은 file:// 로 연 PNG 를 그린 캔버스를 '오염'으로 보고 녹화를 막습니다. 그래서 **녹화할 때만** `js/assets_data.js`(PNG 를 글자로 바꿔 담은 사본)에 있는 그림으로 바꿔 그립니다. 평소 게임 화면은 지금처럼 `assets/` 폴더의 PNG 를 바로 씁니다 → **PNG 를 바꾸면 게임에는 바로 반영**.
- **PNG 를 바꾼 뒤 동영상에도 반영하려면: `tools\에셋갱신.bat` 더블클릭 → 게임 새로고침(F5).** (설치 필요 없음, PowerShell 사용)
- 갱신을 잊은 경우: 녹화 전에 사본이 없거나 크기가 다른 그림을 찾아 알려 줍니다 → **📁 assets 폴더 선택**(지금 파일을 직접 읽어 녹화, bat 불필요) / 그대로 녹화(옛 그림) / 취소. 크기가 같은 그림으로 바꾼 경우는 자동으로 알 수 없으니, 저장 메뉴의 **📁 assets 폴더에서 읽기**를 쓰거나 bat 을 실행하세요.
- 사본에 들어가는 그림: `js/*.js` 에서 경로가 쓰인 PNG(+ `assets/Ghouls/monsters/` 처럼 폴더째 쓰는 곳). 원본 시트(src.png 등)는 제외 → 약 1MB. 녹화할 때만 읽습니다.

- 하단 바(`#stageName`)에 ` · 경기 집중`이 붙습니다(` · B타입`과 함께 쓸 수 있음). 탈출맵은 🚪 이름만 표시합니다.
- 리플레이에 `focusMode`가 기록됩니다. 필드가 없는 옛 리플레이는 끄기로 재생됩니다. 클립/내보내기도 이 필드를 복사합니다.

## 탈출맵

메인 화면에서 **캐릭터 P1·P2와 전투 타입(A/B)을 먼저 고른 뒤** **🚪 탈출맵 (편집·실행)**을 누릅니다. 캐릭터를 고르지 않으면 "먼저 첫 화면에서 캐릭터(P1·P2)를 선택해 주세요" 안내가 뜨고 진입과 실행이 막힙니다. 탈출맵에는 캐릭터를 따로 고르는 기능이 없습니다.

- **이동**: 일반 전투와 똑같습니다. 일정한 속도로 직선 이동하고, 맵 테두리·벽·캐릭터에 부딪히면 반사됩니다. 첫 방향은 시드 난수로 정해지고, 길찾기나 조향·끼임 보정은 전혀 없습니다(완전한 랜덤 이동). 그래서 같은 맵이라도 **시드에 따라 도착 여부와 시간이 크게 달라집니다**.
- **규칙**: 기본은 *먼저 출구에 도착한 캐릭터 승리*(`goal:"race"`)이고, `goal:"coop"`이면 둘 다 도착해야 클리어입니다. `timeLimit`초(기본 120, 최대 600) 안에 못 채우면 실패이고, 협동 모드에서 한쪽이 쓰러져도 실패입니다. 발 위치가 출구 안쪽 6px 이상 들어가야 도착으로 칩니다. 도착한 캐릭터는 그 자리에 멈추고 다른 캐릭터와 충돌하지 않습니다.
- **옵션**: 서로 피해 0(`noDamage`, 기본 켜짐), 공격 불가(`noAttack`, 기본 꺼짐), 속도 배율(`speedMul`, 기본 1). 맵 JSON에 적힌 값이 있으면 그 값을 그대로 씁니다.
- **타일 편집기**: 맵은 40px 타일 격자입니다(720×1280 = 18×32칸, 1080×1920 = 27×48칸, 1440×2560 = 36×64칸).
  - ■ 벽 칠하기 / □ 지우개: 마우스나 터치로 누른 채 끌면 칠해집니다. 빠르게 끌어도 칸이 빠지지 않습니다.
  - P1 시작 / P2 시작: 칸 중심에 놓입니다. 벽 칸에는 놓을 수 없습니다.
  - 🚪 출구: 클릭한 칸이 왼쪽 위가 되고, 크기는 1×1 ~ 4×3칸 중에서 고릅니다.
- **✔ 클리어 검사**: 현재 맵·시드·설정과 첫 화면에서 고른 캐릭터/타입으로 실제 시뮬레이션을 화면 없이 끝까지 돌려 도착 여부와 도착 시각을 보여 줍니다.
- **🎲 시드 탐색(20개)**: 현재 시드부터 20개를 하나씩 시험해서, 처음 클리어되는 시드를 시드 칸에 넣습니다. 진행 상황을 보여 주고 중간에 멈출 수 있습니다. 못 찾으면 다음 20개부터 다시 시작합니다.
- **카메라**: 두 캐릭터 맞춤 / P1 따라가기 / P2 따라가기. 전투 중에는 🎥 버튼으로 바꿉니다. 화면 표시만 바뀌고 시뮬레이션에는 영향이 없습니다.
- **저장**: localStorage(`psEscapeMaps`, 마지막 편집본은 `psEscapeLast`)와 `.psescape.json` 내보내기/가져오기를 지원합니다. 리플레이에는 맵 JSON이 `rec.escape`로 함께 기록됩니다.

### 맵 JSON 형식 (`format:"psescape"`, `v:2`)
```json
{
  "format": "psescape", "v": 2, "name": "샘플 탈출맵",
  "w": 720, "h": 1280, "tile": 40,
  "grid": ["..................", "##########....####", "..."],
  "walls": [{ "x": 0, "y": 400, "w": 400, "h": 40 }],
  "starts": [{ "x": 140, "y": 1180 }, { "x": 580, "y": 1180 }],
  "exit": { "x": 280, "y": 40, "w": 160, "h": 120 },
  "chars": ["genji", "okuyasu"],
  "seed": 2, "timeLimit": 120,
  "rules": { "goal": "race", "noDamage": true, "noAttack": false, "speedMul": 1, "type": "B" }
}
```
- `grid`가 원본입니다. `#`는 벽, `.`는 빈칸이고, 행 수는 ⌈h/40⌉, 열 수는 ⌈w/40⌉입니다. `walls`는 `grid`의 인접 벽 칸을 사각형으로 합친 결과(탐욕적 병합)이고, 사람이 읽기 편하라고 함께 기록합니다. 게임은 이 사각형을 기존 장애물(`b.buildings`, 부서지지 않음)로 넣습니다.
- `chars`와 `rules.type`은 클리어 검사·시드 탐색·실행·내보내기 시점에 **첫 화면 선택값으로 기록**됩니다. 서버가 같은 조건으로 재검증할 수 있게 하기 위해서입니다.
- **구버전 v1(사각형 `walls`만 있음)**: `normalize`가 읽을 때 타일 중심이 사각형 안에 있는 칸을 벽으로 바꿉니다. 시작 지점은 칸 중심으로, 출구는 칸 단위로 맞춥니다. 40px보다 얇은 벽은 칸 중심을 지나지 않으면 사라질 수 있습니다.

### 서버 검증 방식
결과는 **맵 JSON(grid·시작·출구·rules) + seed + chars + rules.type**만으로 정해집니다. 순서는 시드 난수 → `new Battle(A, B, {mode}, 'arena')` → `ESCAPE.apply` → `update(1/120)` 반복입니다.
- 작성자는 클리어되는 시드를 찾아(🎲) 올리고, 서버는 같은 JSON을 그대로 돌려 확인합니다.
- `node tools/escape_check.js 맵.json [--chars a,b] [--mode A|B] [--seed N]`을 실행하면 `{clear, result, steps, time, arrived}`가 출력됩니다. 종료 코드는 0 = 클리어, 1 = 실패입니다.
- DOM이 필요 없습니다. 브라우저의 클리어 검사, 실제 실행, 리플레이와 같은 결과가 나오는 것을 확인했습니다.
- 일반 A/B 전투에는 영향이 없습니다. 모든 훅은 `b.escape`가 있을 때만 동작하고, game.js 변경은 렌더 카메라 2줄뿐입니다.

### 알려진 한계
- 랜덤 이동이므로 출구가 작거나 벽이 촘촘하면 제한 시간 안에 도착하는 시드가 드뭅니다. 큰 출구(2×2 이상)와 넓은 통로를 권장합니다.
- 공격을 허용하면 일부 스킬이 원래 화면(AR) 좌표를 기준으로 위치를 제한해, 큰 맵에서 이펙트 위치가 어색할 수 있습니다.
- 편집기에 실행 취소가 없습니다.

## 탈출맵 온라인 (2단계: 공개 맵, 신고, 관리자)
- **⬆ 맵 올리기**: 로그인이 필요 없습니다. 제목 1~30자, 작성자(선택) 20자, 설명(선택) 200자를 넣습니다.
  - 먼저 **로컬 클리어 검사**를 통과해야 합니다. 그다음 서버가 같은 맵과 시드로 다시 시뮬레이션해서 통과하면 바로 공개 목록에 올라갑니다.
- **🌐 공개 맵 목록**: 최신순입니다. ▶ 플레이(첫 화면에서 고른 캐릭터로 실행), ✎ 편집기로 가져오기, 🚩 신고(확인창)가 있습니다.
  - 목록은 서버를 거치지 않고 맵 저장소에서 직접 읽으므로 서버가 잠들어 있어도 보입니다.
- **미리보기**: 목록 카드마다 검증 시뮬레이션에서 충돌이 가장 많았던 320×240 구역을 보여 줍니다. 벽, S(시작), E(출구), 빨간 점(벽 충돌), 노란 점(캐릭터끼리 충돌)을 표시하고, 오른쪽 위 작은 상자에 전체 맵 속 위치가 나옵니다. 충돌이 적으면 출구 주변을 보여 줍니다. 편집기의 클리어 검사와 시드 탐색 뒤에도 같은 그림이 나옵니다.
- **신고**가 `REPORT_THRESHOLD`(기본 5)개 모이면 맵이 관리자 확인 목록에 들어갑니다. 공개 목록에는 그대로 남습니다.
- **관리자**: 편집기 제목을 2초 안에 5번 누르고 ADMIN_KEY를 입력합니다. 확인 목록에서 비공개 또는 기각을, 비공개 목록에서 복원을 할 수 있습니다. 키는 메모리에만 두고 저장하지 않습니다.
- 설정은 `js/escape_config.js` 한 곳에 있습니다(`ESCAPE_SERVER_URL`, `MAPS_REPO`). 서버 주소가 비어 있으면 '서버가 아직 연결되지 않았어요'가 뜹니다.
- 서버 설명은 `server/README.md`, 처음 설정하는 방법은 `SETUP.md`에 있습니다. 테스트는 `node server/test/run.js`(모의 GitHub)로 돌립니다.

### 탈출맵 특수 요소 (맵 JSON 선택 필드)
- **물 `~`** (grid 문자): 이동 속도가 ×0.6이 되고, 산소가 3초 동안 초당 1씩 줄어듭니다. 물 밖에서는 초당 1.5씩 회복합니다.
  - 산소가 바닥나면 0.5초마다 최대 HP의 8% 피해를 받습니다. **'서로 피해 0'을 켜도 적용**됩니다.
  - 익사하면 그 판은 탈출 실패입니다. 패시브 '오리'(방수)는 영향을 받지 않습니다.
- **일방통행 `^ v < >`** (grid 문자): 다른 칸에서 일방통행 칸으로 **새로 들어오는 순간**의 실제 이동 방향으로 판정합니다.
  - 타일 방향과 45° 이내면 통과합니다. 그보다 크면 직전 위치로 되돌아가고, 들어온 면을 기준으로 벽처럼 튕깁니다(wall 효과음, 돌진은 멈춤).
  - 일방통행 칸 위에서 진행 방향이 45° 이내면 이동 속도가 2배입니다.
  - 같은 방향 칸끼리 옮겨 갈 때는 판정하지 않습니다. 이미 칸 위에 있으면 튕기지 않고 나갈 수 있습니다.
- **파괴벽 `breakables: [{c, r, n, m}]`**: 캐릭터의 몸 충돌(부딪힘·돌진)로만 깎입니다. 공격과 투사체는 무시합니다. 다시 생기지 않습니다.
  - `m:"hits"`: 부딪힐 때마다 1씩 줄어 n번째 충돌에 부서집니다(`n:1` = 즉시 파괴).
  - `m:"hp"`: 엔진 충돌 피해(부딪힘 8 + 속도×0.03, 돌진 90)를 합쳐 n에 닿으면 부서집니다.
  - 같은 캐릭터의 충돌은 엔진 규칙대로 0.15초에 한 번만 셉니다.
- **움직이는 벽 `movers: [{path:[[c,r],…], cells | w,h, at, speed, mode}]`**: path는 상하좌우로 이어진 칸입니다. 모양은 둘 중 하나로 정합니다.
  - `cells: [[dx,dy],…]`(새 형식, 편집기 기본): 경로 칸 기준 상대 오프셋. 최대 64칸, 모양 전체가 8×8칸 안, 각 오프셋 −7~7 정수, 중복 금지. 떨어진 칸도 허용하며 한 덩어리로 같이 움직입니다. 충돌은 칸들을 사각형으로 병합한 일반 벽입니다. 정규화하면 (dy, dx) 순으로 정렬됩니다.
  - `w, h`(기존 형식): 왼쪽 위 칸이 경로를 지나는 w×h 사각형. 그대로 계속 읽고 실행합니다(결과·해시 동일). `cells`와 `w,h`를 같이 쓰면 서버가 거절합니다.
  - `at`은 출발 칸 번호, `speed`는 px/초(20~400)입니다.
  - `mode`는 `pingpong`(왕복) 또는 `loop`(순환, 처음과 끝이 이어진 4칸 이상 경로만)입니다.
  - 위치는 시뮬 시간만으로 정해지므로 결과가 항상 같습니다. 부딪히거나 밀린 캐릭터는 기존 벽 처리로 튕깁니다.
- 편집기 도구:
  - 💧 물, ⇧ 일방통행(방향을 고른 뒤 칠하기), 🧱 파괴벽(부딪힌 횟수 또는 내구도, '즉시 파괴' 버튼).
  - 움직이는 벽은 ① 움직일 경로(칸을 끌어 그리기, 되돌아가면 지워짐) → ② 움직이는 벽(경로 시작 칸 ◎ 둘레에 모양을 칠함, 브러시 크기 적용, 이미 칠한 칸에서 시작한 획은 지우기, 점선 = 경로 끝에 도착했을 때 모양) → ✔ 벽 완성 순서입니다. 속도·왕복/순환은 ② 단계에서 고릅니다.
  - 지우개는 칸, 파괴벽, 그 칸을 지나는 움직이는 벽을 지웁니다. 그리는 중인 벽 모양 칸은 모양에서만 뺍니다.
- 시험: `node tools/escape_feature_test.js`

### 탈출맵 편집기 편의 기능
- **브러시**: 1×1, 2×2, 3×3, 5×5 중에서 고릅니다. 벽, 지우개, 물, 일방통행, 파괴벽에 적용되고 끌어서 칠할 때도 적용됩니다.
  - 홀수 크기는 누른 칸이 가운데이고, 2×2는 누른 칸이 왼쪽 위입니다. 맵 밖 칸은 무시합니다.
  - 마우스를 올리면 칠할 범위가 표시됩니다(잠금 중이면 주황 테두리, 지우개는 빨강).
  - 시작/출구 지정, 경로 그리기는 항상 1칸입니다. 움직이는 벽 모양에는 브러시 크기가 적용되지만 잠금은 적용되지 않습니다.
- **잠금 (🔒, 단축키 L)**: 켜면 칠하기 도구가 빈 칸에만 칠합니다.
  - 빈 칸이 아닌 칸: 벽·물·일방통행 칸, 파괴벽, 움직이는 벽의 경로 칸과 처음 위치 칸.
  - 지우개는 잠금 중에도 그대로 지웁니다.
- **일방통행 방향**: ↑↓←→ 버튼으로 고릅니다. 키보드 방향키나 WASD를 누르면 일방통행 도구로 바뀌고 그 방향이 선택됩니다.
  - 입력칸에 포커스가 있거나 공개 목록·올리기 화면이 떠 있으면 키 입력을 가로채지 않습니다. 방향키를 눌러도 화면은 스크롤되지 않습니다.
- 첫 화면의 '리플레이 열기'와 '탈출맵'은 한 줄에 큰 버튼 2개(높이 48px)로 놓았습니다. 휴대폰처럼 좁거나 터치하는 화면에서는 편집기 버튼도 높이 36~40px로 커집니다.
